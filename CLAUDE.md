## Стек (обновлён после разбора SparkGrid)
- **Бэкенд:** FastAPI + SQLite (WAL-режим обязателен)
- **Фронтенд:** React (веб-интерфейс в браузере)
- **Антидетект:** Camoufox (модифицированный Firefox, open-source, бесплатный) + BrowserForge (генерация fingerprint)
- **Автоматизация:** Playwright API (Camoufox подключается через Playwright)
- **Имитация человека:** кривые Безье для мыши, рандомизированный ввод с клавиатуры, случайные задержки
- **Генерация описаний:** API Claude (опционально)
- **Сторис:** Instagram Web Private API (через Playwright BrowserContext куки)
- **GeoIP:** MaxMind GeoIP2 (автоматическое определение timezone по IP прокси)
- **2FA:** pyotp

### Почему Camoufox, а не Playwright + stealth или Dolphin Anty
- Camoufox = модифицированный Firefox с глубокой подменой fingerprint (canvas, WebGL, AudioContext, fonts, WebRTC блокировка)
- BrowserForge генерирует полноценный fingerprint: UA, platform, screen, codecs, плагины — всё консистентно
- Работает через Playwright API — тот же page.click(), page.fill()
- Бесплатный, open-source, без ограничений по количеству профилей
- Fingerprint генерируется один раз при создании аккаунта и сохраняется в JSON (persistent identity)
- Прокси НЕ влияет на fingerprint seed — можно менять прокси без смены identity
- KNOWN-GOOD версии: camoufox==0.4.11 + playwright==1.53.0

## Находки из разбора SparkGrid (применить в InstaGrid)

### Имитация человека (из ig_human.py)
- Три профиля поведения: balanced (60%), fast (20%), careful (20%) — выбирается детерминировано по SHA256 хешу аккаунта
- Один аккаунт ВСЕГДА ведёт себя одинаково (стабильная "личность")
- Кубические кривые Безье с S-curve ускорением/замедлением (smoothstep: t² × (3 - 2t))
- Overshoot 14%: мышь промахивается мимо цели и корректирует
- Клик через mouse.down() → пауза 45-135мс → mouse.up() (НЕ .click())
- Ввод текста посимвольно, тайпо 1% на соседнюю клавишу → Backspace
- Burst-паттерн: быстрые серии 2-7 символов, потом пауза
- Скролл через 5-10 wheel-импульсов по синусоидальному распределению + случайная коррекция 18%
- Метод dwell: "задумался", стоит на месте с микродвижениями ±8px
- Клик по элементу: beta-distribution (2.6, 2.6) для выбора точки внутри элемента (не в центр)
- Move steps: 14-48 (balanced), масштабируются по расстоянию
- Bend кривой: случайное отклонение 5.5-17% от расстояния, в случайную сторону

### Прогрев fingerprint'а (из web_warmup.py) — ОПЦИОНАЛЬНЫЙ
**Включается только по желанию пользователя через настройки в UI (галочка/тоггл). По умолчанию ВЫКЛЮЧЕН.**
- Отдельный модуль — прогревает браузер через обычный интернет ДО работы с Instagram
- Wikipedia (random), Google, Bing, DuckDuckGo, Google Shopping
- Реактивный движок: на каждом тике читает состояние страницы, классифицирует, реагирует
- Принимает куки (строит cookie jar), обходит consent-попапы
- При капче — уходит на другой поисковик
- Создаёт "историю браузера" — реальные посещения, поиски, чтение статей
- Настройки: длительность прогрева в минутах, количество параллельных профилей
- Запускается как subprocess, не в основном процессе
- Supervisor следит за heartbeat — нет прогресса 75 сек → kill и перезапуск

### Сторис с кликабельной ссылкой (из web_story_link.py)
- Работает через WEB API, не мобильный!
- Пайплайн: JPEG 1080×1920 (Pillow) → POST i.instagram.com/rupload_igphoto → POST www.instagram.com/api/v1/web/create/configure_to_story/ с story_link_stickers
- Куки берутся из Playwright BrowserContext (csrftoken, mid, ig_did, www-claim-v2)
- Визуальный стикер рисуется Pillow на изображении (градиент, тень, иконка, CTA текст)
- Instagram получает только координаты невидимого кликабельного хитбокса
- Необходимые заголовки: x-csrftoken, x-ig-app-id (936619743392459), x-asbd-id (129477), x-requested-with, x-mid, x-ig-device-id, x-ig-www-claim
- User-Agent берётся из текущей страницы (navigator.userAgent), НЕ мобильный
- SparkGrid использует фиксированную позицию x=0.5, y=0.82 — МЫ УЛУЧШАЕМ: рандомизация ±0.05 по X и Y, чуть варьируем размер

### Запуск браузера (из browser_launcher.py)
- persistent_context: куки/кеш сохраняются между сессиями
- Профили в отдельных папках (user_data_dir)
- GeoIP через MaxMind — timezone определяется по IP прокси автоматически
- Язык всегда en-US
- WebRTC всегда заблокирован
- Retry при ошибке прокси: до 3 попыток с экспоненциальной задержкой
- Geometry: пресеты привязаны к ОС (windows_large_1680x1050 и т.д.)

## Архитектура модулей

### 1. Ниши
- Группы аккаунтов
- CRUD: создание, переименование, удаление
- Перемещение аккаунтов между нишами

### 2. Аккаунты
- Массовый импорт: логин:пароль:2FA (сотни за раз)
- Добавление/удаление по одному или пачкой
- Редактирование данных вручную
- Статусы: новый, залогинен, в cooldown, мёртвый (бан)
- При удалении аккаунта — привязанный статический прокси удаляется вместе

### 3. Пулы прокси (два типа)

**Статические:**
- Именованные пулы, CRUD
- Прокси одноразовые при неудачном логине — использовал и удалил навсегда (их сотни тысяч, не жалеть)
- При успешном логине — привязывается к аккаунту, живёт с ним
- Все действия с аккаунтом идут через его привязанный прокси
- При удалении аккаунта — прокси удаляется полностью (не возвращается в пул)
- При запуске проверка: этот IP не использовался ни на одном другом аккаунте

**Мобильные:**
- Ротация IP через API-ссылку провайдера (lteboost, FlashProxy)
- Реальные мобильные прокси, проверка на DC-IP НЕ нужна
- Перед запуском профиля: дёрнуть ссылку ротации → пауза 20 сек → проверить что IP сменился → проверить что IP не встречался в истории → запуск
- TTL на историю IP: если IP использовался >30 дней назад, считать чистым

### 4. Профиль-менеджер (Camoufox + BrowserForge)
- Создание профиля = создание папки + JSON с fingerprint (BrowserForge)
- Fingerprint генерируется один раз и сохраняется навсегда
- Параметры консистентны по ОС (windows/macos/linux)
- GeoIP для timezone по IP прокси
- Запуск: Camoufox в persistent_context + proxy + fingerprint
- Остановка: закрытие контекста, папка сохраняется
- WebRTC заблокирован

### 5. Логин
- Через браузер, мышкой, как человек (HumanInteractor)
- Ввод логина/пароля с человеческой скоростью, burst-typing, тайпо
- 2FA: pyotp генерирует TOTP-код из сохранённого секрета
- Прокликивание попапов: уведомления, ADS, сохранение данных
- После успешного логина: заходит в настройки, отключает приватный профиль
- Параллельно: пул воркеров (5+ окон), атомарный захват задач, по порядку от первого до последнего, пропуск уже отработанных
- При ошибке логина: статический прокси удаляется, берётся следующий из пула, 2-3 неудачи подряд → пароль неверный, аккаунт невалидный

### 6. Прогрев fingerprint'а (ОПЦИОНАЛЬНЫЙ)
- **Включается только через настройки в UI, по умолчанию ВЫКЛЮЧЕН**
- Перед первой работой с Instagram: прогрев через обычные сайты
- Wikipedia, Google, Bing, DuckDuckGo
- Создаёт историю браузера, cookie jar
- Реактивный движок: классификация страниц, обработка consent/captcha
- Настраиваемая длительность (в минутах) и параллельность
- Запускается как subprocess

### 7. Мануальный режим
- Переключение: открываю профиль, лажу руками, делаю что хочу

### 8. Контент
- Загрузка видео: ZIP-архив, распаковывает, привязывает по одному на аккаунт, без повторов
- **UI-плашки:**
  - Если видео больше чем аккаунтов → «Есть резервные видео»
  - Если аккаунтов больше чем видео → «Не все аккаунты заполнены»
- Описания — два режима:
  - Ручной: вставляю пул уникальных описаний, распределяются по одному
  - Автогенерация: ставлю галочку, даю эталонное описание, Claude API генерирует уникальные вариации
- Ручное редактирование видео/описания на конкретном аккаунте

### 9. Постинг рилсов (воркфлоу)
- Логин → отлёжка 6-8 часов
- Заливка 3 рилсов за сессию с прогревом между ними:
  - Прогрев 20 сек - 3 мин: листает ленту, рилсы, 1-3 лайка, "читает" комменты
  - Постит рилс мышкой как человек (HumanInteractor), текст вводит с burst-typing
  - Ждёт подтверждения что видео залито
  - Снова прогрев
  - Следующий рилс
- После 3 рилсов: закрывает профиль
- Пауза 10-14 часов
- Повтор цикла до бана
- Настраиваемое количество рилсов за сессию

### 10. Сторис (через Instagram Web Private API)
- Сессия: куки из Playwright BrowserContext (csrftoken, mid, ig_did, www-claim-v2)
- API-запросы через тот же прокси что и у аккаунта
- User-Agent из текущей страницы (navigator.userAgent)
- Пул фоток (загрузка ZIP-архива)
- Кликабельная ссылка-стикер
- **Позиция стикера рандомизируется:** базовая позиция x=0.5, y=0.82, смещение ±0.05 по X и Y, размер тоже чуть варьируется
- Визуальный стикер рисуется Pillow на изображении (CTA текст, иконка, градиент)
- Описание/стикер текст
- Автопостинг по триггеру: после первого рилса с 10к+ просмотров — сторис раз в сутки максимум, с разбросом ±10-20 минут
- Порог просмотров рандомизирован: 10000-12777
- Статистика сторис если возможно

### 11. Чекер
- Отдельный пул аккаунтов-парсеров (свой импорт, свои прокси)
- Парсит целевые аккаунты каждые 50-90 минут (рандомизация)
- Собирает: просмотры, лайки, комменты, подписчики по каждому рилсу
- Ротация чекеров, рандомизация порядка проверки
- **Подтверждение бана:** минимум 2-3 проверки с разных чекеров
- Если чекер-аккаунт сам забанен — помечается, берётся следующий
- **Порог живых чекеров:** если осталось меньше N — алерт, остановка чекинга
- Панель статистики: графики роста просмотров, подписчиков, лайков, комментов

### 12. Обработка ошибок

**Сетевые:** таймаут/прокси сдох → 2 повтора → если не помогло, берёт другой
**Instagram:** challenge → cooldown 24ч | бан → мёртвый | rate limit → пауза 15-30 мин
**Браузерные:** профиль не запустился → перезапуск, 3 неудачи → пропускает
**Контентные:** видео не загрузилось → пропускает рилс, переходит к следующему
**Непредвиденные:** полный трейсбек в лог, аккаунт пропускается, софт продолжает
**Hard timeout:** 15 минут на весь цикл аккаунта, потом kill

**Перезагрузка при лаге прокси:**
- 30 сек нет ответа → клик адресная строка → Enter
- Вторая попытка → проверяет прокси
- Прокси мёртв → берёт другой
- Прокси жив, Instagram не грузит → пауза 2-3 мин, повтор
- 3 провала → cooldown, следующий

### 13. Логирование
- **Файловые логи:** каждое действие, таймстемп, уровень, модуль, аккаунт, трейсбек. Ротация по дням, хранение 30 дней
- **Логи в базе:** ключевые события для веб-интерфейса. Фильтры по аккаунту, типу, дате
- **Веб-интерфейс логов:** реальное время, фильтры

- Живые / мёртвые / cooldown аккаунты
- Залито рилсов сегодня / сторис
- Количество и типы ошибок

## Уязвимости и решения
1. **2FA-секреты в открытом виде:** НЕ ШИФРОВАТЬ, не приоритет
2. **Чекеры палятся паттерном:** ротация, рандомизация порядка, интервал 50-90 мин
3. **Race condition с прокси:** блокировка на уровне базы, транзакции
4. **Мобильные IP повторяются:** TTL 20 дней на историю
5. **Сессии протухают:** проверка перед каждым действием, автоматический релогин
6. **Memory leak Playwright/Camoufox:** перезапуск каждые 20-30 аккаунтов, мониторинг RAM/CPU
7. **SQLite под нагрузкой:** WAL-режим, connection pool с retry
8. **Очередь воркеров:** атомарный захват задач, по порядку, пропуск отработанных
9. **Подтверждение бана:** минимум 2-3 проверки с разных чекеров
10. **Порог живых чекеров:** алерт + остановка если меньше N
11. **Hard timeout:** 15 минут на цикл аккаунта
12. **Сторис двойной постинг:** флаг «уже запощено», раз в сутки ±10-20 мин
